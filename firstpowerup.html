First power-up.

The robot is assembled. Battery in, breaker on, radio linked, code deployed, enable - and something is wrong. On a real team the fault could belong to anyone: a jammed chain, a dead breaker, a loose wire, a mistyped device ID, a motor wired backward. Your job on the first power-up is not to fix everything yourself. It is to read the symptoms, name the fault, and hand it to the right subteam.

Every robot's first run is a moment of truth. Nothing ever comes up perfectly the first time, and the skill that saves your build season is triage: looking at what the robot is doing, or not doing, and knowing which subteam owns the fix. Flailing on the wrong subsystem burns the hours you do not have.

The bring-up checklist is the same every time, like a pre-ride check on a bike: seat the battery, close the main breaker, link the radio, push the code, then enable. When a step misbehaves, where it misbehaves is your biggest clue.

The mental model

One symptom, three subteams

Almost every first-power-up problem sorts into one of three buckets. Learn the fingerprints and you can point at the owner in seconds.

Mechanical

Anything physical that stops the mechanism: a jammed chain, a bind, a bolt in the way. The tell is a motor that strains - high current - while nothing moves.

Electrical

Power and wiring: a tripped main breaker, a dead battery lead, a loose CAN wire. The tell is missing power or a device that has dropped off the bus.

Code

What the software commands: a wrong device ID, a motor inverted the wrong way, a bad setpoint. The tell is a healthy, powered robot that still does the wrong thing.

Watch for the overlaps. A wrong CAN ID looks electrical at first glance - the mechanism will not move - but the bus is perfectly healthy and the real fix is one line of code. Reading past the surface is the whole game.

Going further · optional

Real bring-up has a longer checklist and better tools. The Driver Station's Diagnostics and CAN/Power tabs show live bus utilization and voltage sag; Phoenix Tuner (for CTRE devices) lists every device on the bus with its ID and firmware, which turns a wrong-CAN-ID hunt into a two-second read. A good team keeps a written bring-up checklist taped in the pit so the same steps happen in the same order every match, and nobody skips the one that bit them last time. When a fault stumps you, the fastest path is almost always to isolate: does power reach the device, does the bus see it, does the code address it, does the mechanism turn by hand.

Checkpoint

Quick check

Pick an answer to see why.

Question 1
You close the main breaker and it snaps right back off. No comms, no lights, the bus reads 0.0 V. Whose fix is this, most likely?
A breaker that will not stay closed, zero volts, and no lights all point one way: power is not getting through. That is electrical - a tripped main breaker, a loose battery lead, or a bad connection. No amount of code or mechanism work matters until the robot has power.
Question 2
The board is all green, the CAN bus is healthy and the controller shows online at ID 4, but you command a move and get nothing - about 0 A, as if the command vanished. Best guess?
Healthy bus, device online, zero current, no movement: the command is going somewhere that does not exist. The code is addressing a device ID the hardware does not use - say the motor is ID 4 but the code asks for ID 5. Nobody answers, so nothing happens and no current flows. Fix it in code to match the hardware, or re-ID the device. The bus being healthy is what rules out a wiring fault.
Question 3
Everything is green, you enable and command the arm up, and the motor strains hard - current spikes past 50 A and you can hear it working - but the arm does not move. Fault and owner?
High current with no movement is the signature of a physical block. The motor is doing exactly what the code asked - pushing hard - but a jammed chain, a bind, or something in the way is stopping the mechanism cold. That is mechanical, and it needs hands on the robot, not a redeploy. Leaving a motor straining like that will pop a breaker or cook the motor, so disable and clear the jam.
